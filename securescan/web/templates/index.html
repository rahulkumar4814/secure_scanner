      Add SecureScan AI to your CI/CD pipeline

      There are two ways to run a scan on every push to GitHub. Use one or both.

      A. GitHub Actions (recommended)

      The scan runs on the GitHub runner. The build fails on Critical findings, a SARIF file feeds the Security tab, and the PDF/JSON reports are uploaded as artifacts.

      B. Webhook to this server

      GitHub calls /api/webhook/github on every push. The server clones and scans the repo, and approvers review Critical/High fixes in this UI.

      Option A - 4 steps

      1. Copy the workflow. Put .github/workflows/securescan.yml from this project into your repository.
      2. Point it at SecureScan. Set SECURESCAN_REPO (repository variable) to the git URL of this SecureScan project, or vendor it as a folder.
      3. Optional AI fixes. Set the repository variable SECURESCAN_MODEL (e.g. llama3.2:3b). The workflow then starts Ollama on the runner. Leave it empty for the fast, deterministic policy-based fixes.
      4. Push. Every push runs the scan. The --fail-on threshold controls when the build breaks.

      How SecureScan AI works
      
      
      A LangGraph agent runs the scan as a state machine. Each step is checkpointed in SQLite, so a scan can pause and wait for a human approver, even across a server restart.
